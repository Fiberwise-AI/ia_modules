# Release Notes v0.2.0

**Release Date**: April 9, 2026
**Type**: Feature Release — Agent Execution, OIDC Auth, Built-in Step Types

## Overview

Version 0.2.0 introduces first-class support for running CLI agents (Claude Code SDK, OpenCode) as pipeline steps, a pluggable OIDC authentication system for agent execution, and a new family of built-in step types that eliminate the need to subclass `Step` for common patterns.

This release also adds an Agent-to-Agent (A2A) protocol client for dispatching work to remote agent servers and packages four collaboration patterns (debate, reflection, planning, agentic RAG) as atomic orchestrator steps.

## Highlights

- **Agent execution framework** with workspace/mode/tool constraints
- **Pluggable OIDC authentication** — local mini OIDC for dev, Keycloak/Auth0/Cognito for production
- **Zero-trust permission enforcement** via custom `a2a` JWT claim and `enforce_agent_claims()`
- **Six built-in step types** — `LLMStep`, `FunctionStep`, `AgentStep`, `A2AStep`, `ParallelStep`, `OrchestratorStep`
- **A2A client** for remote agent dispatch
- **Collaboration patterns** as reusable orchestrator steps
- Unit, integration, showcase, and Playwright e2e test suites

## What's New

### Agent Execution Framework (`ia_modules.agents`)

A new `agents` subpackage provides the infrastructure for running CLI agents as pipeline steps:

- Pluggable executor interface
- Workspace isolation (each run gets a scoped CWD)
- Mode constraints (`research` vs `execute`)
- Tool allow-lists enforced at execution time
- Support for Claude Code SDK and OpenCode out of the box

### Agent Authentication & Permissions

Production-ready OIDC authentication for agent execution, with a zero-trust permission model.

**Pluggable IDP Adapters:**
```python
from ia_modules.agents.auth import get_adapter

# AGENT_AUTH_MODE=local -> MiniOIDCAdapter (built-in, no external IDP needed)
# AGENT_AUTH_MODE=oidc  -> KeycloakAdapter (OIDC_DISCOVERY_URL, OIDC_AUDIENCE, ...)
adapter = get_adapter(db=my_db)
claims = await adapter.validate_token(bearer_token)
```

**Zero-Trust Claim Enforcement:**
```python
from ia_modules.agents.permissions import enforce_agent_claims

# Raises ClaimsViolation if the JWT doesn't permit this CWD/mode/tool combination
enforce_agent_claims(
    claims,
    cwd="/data/apps/app-123/workspace",
    mode="research",
    tools=["Read", "Glob", "Grep"],
)
```

The custom `a2a` JWT claim scopes each token to:
- **Allowed CWDs** (path patterns, or `app_id` fallback)
- **Allowed modes** (e.g., `research`, `execute`)
- **Allowed tools** (e.g., `Read`, `Write`, `Bash`)

Mismatches raise `ClaimsViolation(ValueError)` before any executor runs.

### Built-in Step Types

Six new step types eliminate subclassing for common patterns:

| Step | Purpose |
|------|---------|
| `LLMStep` | Send a prompt to a CLI agent, get text back |
| `FunctionStep` | Wrap any async callable (vote tally, routing, aggregation) |
| `AgentStep` | Run a CLI agent (Claude Code SDK, OpenCode) locally with workspace and tool constraints |
| `A2AStep` | Dispatch work to a remote A2A server via JSON-RPC |
| `ParallelStep` | Fan-out — run child steps concurrently |
| `OrchestratorStep` | Run a collaboration pattern (debate, reflection, planning, agentic RAG) as one atomic step |

**Example:**
```python
from ia_modules.pipeline import LLMStep, FunctionStep, ParallelStep, A2AStep

summarizer = LLMStep(
    name="summarize",
    system_prompt="Summarize the following text concisely.",
    model="claude-sonnet-4-20250514",
)

async def tally_votes(context):
    votes = context.get_data("votes", [])
    return {"winner": max(set(votes), key=votes.count)}

tally = FunctionStep(name="tally", fn=tally_votes)

reviewers = ParallelStep(
    name="all_reviewers",
    children=[reviewer_1, reviewer_2, reviewer_3],
)

remote = A2AStep(
    name="remote_analysis",
    server_url="http://a2a-server:3008",
    mode="research",
    tools=["Read", "Glob", "Grep"],
)
```

### A2A (Agent-to-Agent) Client

`A2AExecutor` dispatches work to remote A2A-protocol servers:
- JSON-RPC request/response with streaming support
- Bearer token authentication
- Automatic JWT minting for local development
- Usable directly or via the new `A2AStep`

### Collaboration Patterns

Four patterns are now packaged as reusable orchestrators and can run as an atomic `OrchestratorStep`:
- **Debate** — multiple agents argue positions, a judge selects a winner
- **Reflection** — draft → critique → revise loop
- **Planning** — planner decomposes into steps, executor runs them
- **Agentic RAG** — retrieval-augmented reasoning with tool use

## Breaking Changes

All existing `Step` subclasses and pipeline JSON definitions continue to work unchanged. `LLMProviderService.generate_completion()` and the LiteLLM-based completion API have been removed — use `LLMStep` / `AgentStep` instead; the service remains as a lightweight `provider_id → api_key/model` registry.

## Migration Guide

No migration is required. To adopt the new features:

**To use built-in step types instead of subclassing:**
```python
# Before
class MySummarizer(Step):
    async def execute(self, data):
        # ... call LLM ...
        return {"summary": ...}

# After
summarizer = LLMStep(name="summarize", system_prompt="...", model="...")
```

**To enable agent auth:**
```bash
# Local development (default)
export AGENT_AUTH_MODE=local

# Production
export AGENT_AUTH_MODE=oidc
export OIDC_DISCOVERY_URL=https://keycloak.example.com/realms/my-realm/.well-known/openid-configuration
export OIDC_AUDIENCE=my-agent-audience
```
